# Governance

ApacheMinaSSHD.NET is maintained by **SERALYNX LLC** — a Critical Infrastructure Engineering firm supporting Physical and Technological Advancement.

## Decision-Making

The SERALYNX LLC maintainer team makes all final decisions about the project, including accepting or rejecting contributions, setting the roadmap, and managing releases. Decisions are guided by the project's core goal: providing a .NET-facing Apache MINA SSHD wrapper for SFTP and SCP server features that hides Java, IKVM, and Apache MINA types from normal application code.

## Roles and Responsibilities

| Role | Responsibility |
|------|---------------|
| **Maintainer** (SERALYNX LLC) | Reviews contributions, manages releases, sets roadmap, resolves disputes, handles security reports |
| **Contributor** | Submits pull requests, reports issues, improves documentation, participates in discussions |

## How Decisions Are Made

1. **Routine changes** (bug fixes, documentation, small improvements) — accepted at maintainer discretion.
2. **Significant changes** (new features, API changes, breaking changes) — reviewed against project scope. The maintainer team evaluates alignment with project goals, maintenance burden, and community need.
3. **Disputes** — resolved by the maintainer team. If a decision is contested, the maintainers will explain their reasoning.

## Code of Conduct

All contributors must adhere to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Release Process

Releases are tagged with versioned Git tags (`v*.*.*.*`) and published to NuGet. See `RELEASE-NOTES.md` for the release process.
